▶ PlayBlazor
NuGet GitHub

Every [Parameter] becomes a control.

Point PlayBlazor at any Blazor component library and get a live playground: typed controls, the matching Razor markup and an event log, with no stories to write by hand.

Open the MudBlazor playground View on GitHub

Also live for Fluent UI Blazor and DaisyBlazor, or compare all three.

dotnet add package PlayBlazor One package. Its only dependency is Microsoft.AspNetCore.Components.Web.

The real one, running in the MudBlazor showcase

A live specimen surrounded by panels PlayBlazor generated from the component: its parameter graph, typed controls, the Razor it would take and every EventCallback it fired. The Share button turns the current state into a link.

Screenshot of the MudButton explorer after picking the Filled primary example and clicking the button twice.

Pick a library to explore

The same playground, pointed at three component libraries. PlayBlazor depends on none of them: each one is only the subject of its showcase.

Expect a short wait on the first visit. Each showcase runs .NET in your browser, so it first downloads several megabytes of Blazor WebAssembly runtime and library code; later visits load from cache. If one never starts, your browser may be blocking WebAssembly: run it locally with dotnet run from the repository.
